# Why extremes in chaotic systems?

A chaotic dynamical system creates a sequence that is deterministic and still difficult to predict. Extreme-value analysis adds another layer: rare events are shaped not only by the marginal distribution of an observable, but by the geometry and recurrence structure of the dynamics.

## From a dynamical system to a time series

Let \(T : \mathcal X \to \mathcal X\) be a dynamical system and let \(\varphi : \mathcal X \to \mathbb R\) be an observable. Starting from \(x_0\),

\[
X_t = \varphi(T^t x_0)
\]

is a scalar time series.

The key point is that \(X_t\) and \(X_{t+1}\) are generated by the same orbit. They are not independent draws merely because the trajectory looks irregular.

!!! note "Deterministic does not mean independent"
    Chaos creates sensitive dependence on initial conditions. Statistical independence is a different concept. EVT for dynamical systems has to respect both facts.

## Maxima and the IID benchmark

Write

\[
M_n = \max\{X_1,\ldots,X_n\}.
\]

For an IID sequence with distribution function \(F\), choose thresholds \(u_n\) such that

\[
n\{1-F(u_n)\} \to \tau.
\]

Then the classical limiting relation is

\[
\Pr(M_n \le u_n) \to e^{-\tau}.
\]

For a dependent stationary process satisfying suitable conditions, a common limit is

\[
\Pr(M_n \le u_n) \to e^{-\theta\tau},
\]

with \(\theta \in (0,1]\).

The parameter \(\theta\) is the **extremal index**.

## What the extremal index changes

When \(\theta=1\), extreme events behave asymptotically as if they do not cluster. When \(\theta<1\), exceedances tend to arrive in episodes.

Under standard cluster-process conditions,

\[
\mathbb E[K] \approx \frac{1}{\theta},
\]

where \(K\) is the limiting cluster size. This is a useful interpretation, not a universal finite-sample identity.

The practical consequence is important: counting every exceedance as a separate independent event can overstate the effective amount of tail information.

## Why periodic structure matters

In chaotic maps, high values of an observable can recur when the orbit repeatedly visits a small region of state space. If that region is close to a periodic orbit, short returns can create highly structured clusters.

That is one reason this package keeps dynamical diagnostics close to the EVT machinery. A fitted GPD may describe exceedance magnitudes while still saying little about *why* those exceedances arrive in clusters.

## Three layers of analysis

~~~mermaid
flowchart TB
    D[Dynamical system] --> O[Observable / trajectory]
    O --> S[Statistical dependence]
    S --> E[Extreme-event process]
    E --> M[GEV / GPD / PPP / r-largest]
    E --> C[Extremal index / clusters]
    O --> R[Lyapunov / recurrence / entropy]
    R --> I[Joint interpretation]
    M --> I
    C --> I
~~~

### 1. Dynamics

Ask what system generated the trajectory and whether the orbit is periodic, chaotic, synchronized, or transient.

Useful functions include:

- <code>estimate_lyapunov_exponent()</code>
- <code>lyapunov_spectrum()</code> and system-specific wrappers
- <code>recurrence_plot()</code>
- <code>rqa()</code>
- <code>symbolize()</code>, <code>block_entropy()</code>, and <code>source_entropy()</code>

### 2. Dependence

Ask whether exceedances are isolated or clustered, and whether dependence decays sufficiently quickly for the intended asymptotics.

Useful functions include:

- <code>acf_decay()</code>
- <code>mixing_coefficients()</code>
- <code>d_check()</code>
- <code>extremal_index_runs()</code>
- <code>extremal_index_intervals()</code>

### 3. Tail model

Only then ask which asymptotic representation is most useful:

- block maxima \(\rightarrow\) GEV;
- peaks over threshold \(\rightarrow\) GPD;
- exceedance times + magnitudes \(\rightarrow\) point process;
- multiple top observations per block \(\rightarrow\) r-largest likelihood.

## What chaoticds is trying to avoid

The package is deliberately not based on the workflow

> simulate something chaotic → ignore dependence → fit a standard tail model → report a return level.

A more defensible workflow is

> understand the orbit → define extremes → diagnose dependence and clustering → fit the tail model → quantify uncertainty → check sensitivity.
